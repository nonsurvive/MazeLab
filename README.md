# MazeLab — 迷宫生成与求解可视化

为《数据结构与算法》课程大作业完成的交互式迷宫实验工具：**三种算法生成迷宫、
四种算法求解、动画演示、指标统计与批量对比实验**，仅依赖 Python 标准库。

- 对象：学习图搜索与栈/队列/堆/并查集的同学，以及需要一个直观演示工具的算法课教学场景。
- 解决的问题：教材上的搜索算法只有静态伪代码，「探索过程长什么样、不同算法差在哪」
  看不见摸不着。MazeLab 把生成与求解过程逐步动画化，并用同一口径的指标
  （探索节点数、峰值前沿、路径长度、耗时）把差异量化。
- 已完成功能：见 [功能一览](#功能一览)。

## 功能一览

| 模块 | 内容 |
| :--- | :--- |
| 迷宫生成 | 递归回溯（显式栈 DFS）、随机 Prim、Kruskal（并查集）|
| 有环迷宫 | braid：按概率消除死胡同，把生成树变成有环图（对比实验的关键前提）|
| 迷宫求解 | BFS、DFS（显式栈）、A*（曼哈顿启发 + 二叉堆）、贪心最佳优先 |
| 可视化 | tkinter：生成/求解逐帧动画，速度可调，暂停/继续，左键设起点、右键设终点 |
| 算法对比 | GUI「一键对比」表格；CLI `--solve all` 单迷宫对比；`--bench` 批量实验输出 CSV + 汇总表 |
| 验证 | 60 个 pytest 用例，含「完美迷宫路径唯一」等强性质对照 |

## 安装与运行

环境：**Python 3.10+（开发用 3.13.2）**，无第三方运行时依赖（tkinter 为标准库自带）。
开发测试需要 pytest（见 `requirements.txt`）。

```bash
# 1. 启动图形界面（推荐第一次这样运行）
python main.py

# 2. 命令行演示：生成 31x31 迷宫，四种算法对比求解，打印字符画
python main.py --size 31 --solve all --seed 42 --ascii

# 3. 运行全部测试（60 个用例）
python -m pytest tests -q

# 4. 批量对比实验（约 1 分钟，输出汇总表并写 CSV）
python main.py --bench --trials 20 --bench-csv examples/benchmark.csv
```

GUI 使用：选择生成算法与大小 → 「生成迷宫」观看逐帧拆墙动画 → 选择求解算法 →
「求解动画」观看搜索过程与最终路径（橙色）；**左键点击设起点、右键点击设终点**；
「环路%」大于 0 时生成的迷宫带环（此时 DFS/贪心可能不再最优，对比才有悬念）；
「一键对比」在当前迷宫上跑全部四种算法并列出指标。

完整 CLI 参数见 `python main.py --help`；更多示例输出见 [examples/](examples/)。

## 课程知识与核心设计

### 数据结构选型

| 数据结构 | 用在哪 | 为什么 |
| :--- | :--- | :--- |
| 哈希表（dict/set）| 迷宫墙体 `walls[cell] -> {N,S,E,W}`、visited/parent/closed 集合 | 邻居查询与判重 O(1)，是所有算法的地基 |
| 栈 | 递归回溯生成、DFS 求解 | 后进先出 = 「一条路走到黑，撞墙再回溯」；生成器用显式栈避免 101×101 时递归深度超限 |
| 队列（deque）| BFS 求解 | 先进先出保证按层扩展 → 无权图最短路 |
| 二叉堆（heapq）| A* / 贪心、（对比）Prim 的优先级思想 | 按 f(n)=g+h 取最小，O(log n) |
| 并查集 | Kruskal 生成 | 路径减半 + 按秩合并，判「两端是否已连通」近似 O(α(n)) |

### 三个关键设计决策

1. **「格子 + 墙」模型，墙体信息两侧各存一份**（`maze.py`）。
   拆墙/筑墙只通过 `carve()/add_wall()` 进行，强制同步两侧，结构上杜绝了
   「A 能到 B、B 却不能到 A」的不一致状态；`carve` 拒绝重复拆墙和拆边界墙，
   生成算法不可能把迷宫拆漏。
2. **算法输出事件流，界面只做回放**（`generators/`、`solvers/`、`gui.py`）。
   生成器是 `yield` 事件的生成器函数，求解器接受 `on_event` 回调；GUI 按帧消费事件
   着色。核心逻辑与界面完全解耦——CLI、测试、基准实验都在无界面条件下复用同一份算法代码。
3. **四种求解器共用同一套指标口径**（`solvers/base.py`）。
   `expanded`（出堆/出队并展开的节点数）、`seen`（标记过的节点数）、
   `frontier_peak`（前沿结构峰值，均按去重口径）在四个算法中定义一致，
   这是对比实验成立的前提。

### 复杂度与验证要点

- 生成：回溯 O(n)；Prim O(n)（前沿用「集合判重 + 列表 swap-pop」实现 O(1) 随机删除）；
  Kruskal O(E·α(E))，E ≈ 2n。三者产出均为**生成树**，由测试验证
  （连通 + 边数 = n − 1）。
- 求解：时间均 O(V + E)（A*/贪心乘以堆操作因子 log），空间 O(V)。
- **正确性验证的锚点：完美迷宫任意两点简单路径唯一。** 因此在树形迷宫上，
  四种算法必须返回逐格相同的路径——这是极强的已知答案对照
  （`test_perfect_maze_all_solvers_return_identical_path`）。
- braid 加环后树变有环图：BFS 与 A*（可采纳且一致的曼哈顿启发）仍必须给出
  相等的最优路径长度，DFS/贪心允许更长但不允许更短
  （`test_braided_maze_bfs_astar_optimal_dfs_greedy_not_shorter`）。

## 测试与结果

```text
$ python -m pytest tests -q
```

| 测试文件 | 覆盖内容 |
| :--- | :--- |
| `test_maze.py` | 模型边界条件：重复拆墙、拆边界墙、不相邻拆墙、越界格子均报错；墙体两侧一致；ASCII 渲染形状 |
| `test_generators.py` | 三种算法 × 5 种形状（含 1×1、非方阵）：连通 + 生成树边数 + 同种子可复现 + 边界墙完好；braid p=1 消除全部死胡同 |
| `test_solvers.py` | **完美迷宫四算法路径逐格一致**（3 种生成 × 3 种子）；有环迷宫 BFS/A* 最优且相等；终点封死返回不可达；起点=终点；开阔网格与树形迷宫上的空间开销对比 |
| `test_gui_smoke.py` | GUI 构建 → 生成 → 求解 → 一键对比全流程不异常（无显示环境自动跳过） |

批量实验（2 生成算法 × 4 规模 × 20 迷宫 × 4 求解算法）的完整数据与分析见
**[docs/benchmark.md](docs/benchmark.md)**（原始数据
[examples/benchmark.csv](examples/benchmark.csv)）。核心结论：完美迷宫上四算法
路径一致；BFS 在 Prim 迷宫上探索近全图（10194/10201）；「DFS 省空间」并非无条件——
开阔网格上 DFS 栈峰值 1251 vs BFS 波前 51，而树形迷宫上相反。

## 局限与改进

已知局限：

- 仅支持方形/矩形完美迷宫 + braid 加环，不支持手工绘制墙体（当前只能改起终点）；
- 动画在大迷宫（121×121）上 tkinter 绘制较慢，一次性画出全部墙线；
- 对比实验未覆盖「环路比例 × 探索规模」的二维扫描；
- 无持久化：迷宫不能存档/导出图片。

计划改进：

- [ ] 支持鼠标画墙/擦墙，编辑生成结果；
- [ ] 增加 Dijkstra（非负权推广）与双向 BFS，接入同一指标体系；
- [ ] braid 二维实验 + 曲线图（matplotlib 或纯 SVG 输出）；
- [ ] 迷宫导出 PNG/SVG，便于讲义插图。
